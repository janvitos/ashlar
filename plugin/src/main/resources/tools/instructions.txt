Ashlar: tools for reading and building in a live Minecraft (Paper) server. Nineteen tools are available - load them by name when needed.

Safety: Preserve rollback protection when changing existing terrain/structures: every writing call returns a journal id; undo one call with mc_restore {journal:"jrn-..."}, not a whole-region restore. Prefer mc_build snapshot:true over a separate snapshot call. Journals and snapshots store block states, sign text and decorative entities (paintings, item frames, armor stands), not container inventories. Do not automatically restore a whole region for a small defect. When a call is rejected for a protected region, change the plan to stay outside it; pass override only when the user explicitly asks. mc_command is not checked against protected regions.
Coordinates: X east, Z south, Y up; from/to corners are inclusive. mc_build `transform` makes its coordinates local; other tools use world coordinates.

Default lightweight workflow: mc_players only when player context/safety is needed; one mc_survey before a substantial build, reusing a recent relevant survey; mc_build; one mc_render of the finished substantial build, first-person at eye height from where players arrive. Prefer a few bulk build calls; do not request detailed:true routinely. Do not stack mc_plan, dryRun, preflight and mc_verify on ordinary builds or repeat whole-build checks; they are escalation for a requested preview or a concrete placement risk. Stop once the result looks satisfactory. All builds still receive mandatory plugin-side structural safety validation, without extra agent tool calls.
If a check reveals a specific issue, inspect only the affected area and make a targeted correction; if it remains unresolved, explain it rather than looping. Understand existing controls or furnishings before removing them to satisfy preflight; a failed check is not permission to delete them.
Full exact verification is opt-in: only when the user explicitly requests exact block-state verification, not because a build is large or photo-based. Then mc_verify prepare BEFORE mc_build, check afterwards, and mc_repair from the latest comparisonId.

Tools:
- read: mc_status (health, queue), mc_players (position, facing, look target: "here", "in front of me"), mc_survey (terrain heights), mc_inspect (exact blocks, signs, entities), mc_render (PNG views incl. first-person)
- check, read-only: mc_sightline (visibility), mc_walk (walkable paths, reachable doors/beds/stairs), mc_light (dark spawn spaces, light positions), mc_diff (live box vs snapshot/cells/blueprint), mc_plan (preview a build)
- write: mc_build (fills, curved `shapes`, blocks/signs, `text`, cells, blueprints, `entities`), mc_repair (fix mc_diff/mc_verify mismatches), mc_restore (undo a journal or restore a snapshot), mc_command (console escape hatch)
- other: mc_snapshot (save regions, list journals), mc_protect (protected regions), mc_blueprint (generate/save/tag designs; no world writes), mc_export (box to file), mc_verify (opt-in exact verification)
A blueprint build reply ends with a "Blueprint:" line; mark progress with mc_blueprint tag (status draft/built/approved).

Photo-reference reconstruction: Ashlar does not fetch or analyze photos; use supplied images, or the calling agent's image/web tools for a named structure, or ask for images. Before placement give a short brief: front direction, scale anchor, approximate width:depth:height, main masses, three to five distinctive features, palette and uncertainty. Separate observed features from inferred geometry and unknown/hidden areas; do not invent measured dimensions or an exact unseen interior. Prioritize silhouette, proportions and facade rhythm before ornament; explain material approximations; do not invent a similarity score. 'As close as possible' does not automatically request exact block-state auditing: mc_verify compares blocks with a frozen specification, not with a photograph.
